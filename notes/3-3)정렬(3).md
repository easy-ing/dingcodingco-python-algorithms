# 딩코딩코 Chapter3- 정렬 (3)

## **1) Merge Sort 한 줄 정의**

**배열을 계속 반으로 쪼개서(분할), 각 조각을 정렬한 뒤, 다시 두 개씩 정렬된 상태로 합치면서(병합) 전체를 정렬하는 알고리즘**이야.

→ 대표적인 **Divide & Conquer(분할 정복)** 정렬.

---

## **2) 어떻게 작동해? (동작 흐름)**

예: [5, 2, 4, 7, 1, 3, 6]

### **(1) 분할(Divide)**

배열을 **반으로 계속 쪼개서** 원소 1개짜리까지 만든다.

- [5,2,4,7] / [1,3,6]
- [5,2] / [4,7] / [1,3] / [6]
- [5] [2] [4] [7] [1] [3] [6]

원소 1개는 이미 정렬된 상태라고 볼 수 있어.

### **(2) 병합(Conquer / Merge)**

이제 **정렬된 두 배열을 합치면서 정렬**해.

- [5] + [2] → [2,5]
- [4] + [7] → [4,7]
- [2,5] + [4,7] → [2,4,5,7]
- [1] + [3] → [1,3]
- [1,3] + [6] → [1,3,6]
- 마지막으로 [2,4,5,7] + [1,3,6] → [1,2,3,4,5,6,7]

핵심은 **“병합할 때 두 배열이 이미 정렬돼 있으니, 투 포인터로 작은 것부터 뽑아 넣으면 된다”**는 점.

---

## **3) 시간/공간 특성 (시험/면접 단골)**

- **시간 복잡도:** O(N log N)
    - 분할 단계가 log N번
    - 매 단계마다 합치는 데 N
- **공간 복잡도:** 보통 O(N) (추가 배열 사용)
- **안정 정렬(Stable):** 가능/보장됨 (같은 값의 상대 순서 유지)
    - 구현에서 “같을 때 왼쪽 먼저”를 지키면 안정성이 유지돼.

## **4) 자바로 구현 (가장 표준적인 형태)**

아래 코드는 **추가 배열(temp)** 하나를 만들어서 재귀로 정렬하는 대표 구현이야.

```java
import java.util.Arrays;

public class MergeSort {

    public static void mergeSort(int[] arr) {
        if (arr == null || arr.length <= 1) return;
        int[] temp = new int[arr.length];
        mergeSort(arr, temp, 0, arr.length - 1);
    }

    private static void mergeSort(int[] arr, int[] temp, int left, int right) {
        if (left >= right) return; // 원소 1개면 종료

        int mid = left + (right - left) / 2;

        mergeSort(arr, temp, left, mid);
        mergeSort(arr, temp, mid + 1, right);

        merge(arr, temp, left, mid, right);
    }

    // arr[left..mid] 와 arr[mid+1..right] 는 "이미 정렬된 상태"라고 가정하고 병합
    private static void merge(int[] arr, int[] temp, int left, int mid, int right) {
        int i = left;      // 왼쪽 배열 시작
        int j = mid + 1;   // 오른쪽 배열 시작
        int k = left;      // temp에 채워 넣을 위치

        while (i <= mid && j <= right) {
            // 안정 정렬을 원하면 같을 때 왼쪽(i)을 먼저 뽑는 <= 사용
            if (arr[i] <= arr[j]) {
                temp[k++] = arr[i++];
            } else {
                temp[k++] = arr[j++];
            }
        }

        // 왼쪽 잔여 처리
        while (i <= mid) temp[k++] = arr[i++];

        // 오른쪽 잔여 처리
        while (j <= right) temp[k++] = arr[j++];

        // temp 결과를 원본 arr로 복사
        for (int idx = left; idx <= right; idx++) {
            arr[idx] = temp[idx];
        }
    }

    public static void main(String[] args) {
        int[] arr = {5, 2, 4, 7, 1, 3, 6};
        mergeSort(arr);
        System.out.println(Arrays.toString(arr));
    }
}
```

## **5) “언제 쓰는지” (현실적인 선택 기준)**

Merge Sort는 이런 상황에서 특히 좋아.

### **✅ (A) “최악의 경우도 안정적으로 빠르게” 정렬하고 싶을 때**

퀵정렬은 평균적으로 빠르지만, 특정 경우 최악이 O(N^2)가 될 수 있잖아.

Merge Sort는 **항상 O(N log N)**이라 성능 예측이 안정적이야.

### **✅ (B) 안정 정렬이 필요할 때**

예: (학생이름, 점수) 정렬에서 **점수가 같을 때 원래 입력 순서를 유지**해야 하는 경우

→ 병합 과정에서 <=로 처리하면 안정성이 유지돼.

### **✅ (C) 연결 리스트(Linked List) 정렬할 때**

배열은 추가 메모리가 들지만, **연결 리스트는 merge가 포인터 연결로 효율적**이라 병합정렬이 잘 맞아.

### **✅ (D) 외부 정렬(External Sort)**

데이터가 너무 커서 메모리에 다 못 올릴 때

→ 파일을 나눠서 정렬하고 “병합”하는 방식이랑 merge sort 구조가 거의 똑같아.

## **6) 언제는 별로야?**

- **추가 메모리(O(N))가 부담일 때**
    
    (메모리 타이트하면 in-place 정렬(예: heap sort) 고려)
    
- **배열에서 상수 시간이 중요한 초고성능 상황**에서는
    
    보통 자바 내장 정렬(TimSort/dual-pivot quicksort 등)처럼 최적화된 구현이 유리할 수 있어.
