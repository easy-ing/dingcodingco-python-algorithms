# 딩코딩코 Chapter3- 정렬 (1)

## **1) Sorting의 개념**

### **정렬이란?**

- **여러 데이터(숫자, 문자열, 객체 등)를 특정 기준(오름차순/내림차순 등)에 맞게 순서를 재배치**하는 것.
- 예: [5, 2, 9, 1] → 오름차순 정렬 → [1, 2, 5, 9]

### **정렬이 필요한 이유**

- **탐색을 빠르게** 할 수 있음 (대표적으로 이진 탐색은 정렬이 필요)
- **데이터를 보기 좋게** 정리
- **중복 처리/그룹화** 같은 후속 작업이 쉬워짐

### **정렬 기준**

- 오름차순(Ascending): 작은 값 → 큰 값
- 내림차순(Descending): 큰 값 → 작은 값
- 객체 정렬: “점수”, “이름”, “날짜” 같은 **필드 기준**으로 정렬 가능 (Comparator/Comparable로 확장)

### **정렬 알고리즘에서 자주 보는 개념**

- **시간 복잡도(Time Complexity)**: 입력 크기 N에 따라 실행 시간이 얼마나 늘어나는지
    - 예: O(N^2), O(N log N) 등
- **공간 복잡도(Space Complexity)**: 추가 메모리를 얼마나 쓰는지
- **안정 정렬(Stable Sort)**
    - 값이 같은 데이터가 있을 때 **원래의 상대적 순서가 유지**되면 안정 정렬
- **제자리 정렬(In-place Sort)**
    - 추가 배열 같은 큰 메모리 없이 **배열 내부에서 교환만으로 정렬**하면 제자리 정렬

## **2) 버블 정렬(Bubble Sort)**

### **핵심 아이디어**

- **인접한 두 원소를 비교**해서 순서가 잘못되었으면 **서로 교환(swap)**한다.
- 한 번의 “패스(pass)”가 끝나면 가장 큰 값(오름차순 기준)이 **맨 뒤로 ‘떠오르듯’ 이동**한다 → 그래서 Bubble.

### **동작 방식(오름차순 기준)**

1. arr[0] vs arr[1] 비교 → 크면 교환
2. arr[1] vs arr[2] 비교 → 크면 교환
3. 끝까지 반복하면 맨 뒤가 가장 큰 값으로 확정
4. 다음 패스에서는 맨 뒤는 제외하고 반복

### **시간/공간 특징**

- 시간 복잡도
    - 평균/최악: **O(N²)**
    - 최선(이미 정렬된 경우 + 최적화 적용 시): **O(N)**
- 공간 복잡도: **O(1)** (추가 메모리 거의 없음)
- 안정 정렬: **Yes** (같은 값은 일반적으로 순서 유지)
- 제자리 정렬: **Yes**

## **3) 자바 구현 코드 (기본)**

```sql
public class BubbleSortBasic {
    public static void bubbleSort(int[] arr) {
        int n = arr.length;

        for (int i = 0; i < n - 1; i++) {            // 패스 횟수
            for (int j = 0; j < n - 1 - i; j++) {    // 뒤쪽은 이미 확정이므로 -i
                if (arr[j] > arr[j + 1]) {          // 오름차순 기준
                    int temp = arr[j];
                    arr[j] = arr[j + 1];
                    arr[j + 1] = temp;
                }
            }
        }
    }
}
```
