# 딩코딩코 Chapter2 - 재귀함수

# **재귀함수(Recursion)**

## **1) 재귀함수란?**

재귀함수는 **함수가 자기 자신을 다시 호출하는 방식**으로 문제를 해결하는 함수이다.

큰 문제를 **작은 문제로 쪼개서(분할)** 같은 방식으로 반복 처리할 때 유용하다.

예) factorial(5)

→ 5 * factorial(4)

→ 5 * 4 * factorial(3) … 이런 식으로 내려감

---

## **2) 재귀의 필수 조건 2가지**

재귀가 성립하려면 아래 두 개가 반드시 있어야 한다.

### **✅ (1) 종료 조건(Base Case)**

- “언제 멈출지”를 정하는 조건
- 이게 없으면 무한 호출로 **StackOverflowError** 발생

### **✅ (2) 재귀 호출(Recursive Case)**

- 문제를 더 작은 문제로 바꿔서 다시 호출하는 부분
- 매 호출마다 **종료 조건에 가까워져야 함**

---

## **3) 재귀가 동작하는 방식 (콜 스택)**

재귀 호출은 함수가 호출될 때마다 **스택(Stack)** 에 쌓인다.

- f(3) 호출 → 스택에 f(3)
- 내부에서 f(2) 호출 → 스택에 f(2)
- 내부에서 f(1) 호출 → 스택에 f(1)
- 종료 조건 도달 후, 반환(return)되면서 스택이 하나씩 빠짐

📌 그래서 재귀는 **깊이가 너무 깊으면 위험**하다. (스택이 꽉 차서 터짐)

# **5) Java 예제**

## **예제) 팩토리얼 (Factorial)**

n! = n * (n-1)!, 단 0! = 1

```java
public class RecursionFactorial {

    static int factorial(int n) {
        // 종료 조건(Base Case)
        if (n == 0) return 1;

        // 재귀 호출(Recursive Case)
        return n * factorial(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(factorial(5)); // 120
    }
}
```

# **6) 재귀 문제 풀 때 체크리스트**

- 종료 조건이 확실히 있는가?
- 매 호출마다 문제 크기가 줄어드는가?
- 스택 깊이가 너무 깊어질 위험은 없는가?
- 반복문/DP로 더 안전하게 풀 수 있는 문제는 아닌가?
